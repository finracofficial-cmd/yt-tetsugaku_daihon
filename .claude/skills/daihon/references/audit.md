# 工程4:出力前の自己監査

**不合格があれば、削るのではなく増築してから再確認する。**

---

## 第1段階:機械チェック

```bash
python3 tools/audit.py output/<ディレクトリ>/03_台本.txt
```

自動判定される項目:

| 項目 | 基準 |
|---|---|
| 本文の総字数 | 6,000字以上(目安上限7,600字) |
| 段落数 | 既定40。ビート40を使う場合41(38未満はFAIL) |
| ビート別字数 | 各ビートが目標字数の80パーセント以上 |
| 重量級ビート10・17・24・30・37 | 各200字以上 |
| ブロック末尾13・20・27・32・36 | 疑問文で終わる |
| 裏切り予告(ビート13)の位置 | 全体の22〜55パーセント地点 |
| **二人称の呼びかけ** | 「あなた」「我々」「〜してみてほしい」の合計8回以上(FAIL) |
| **想定反論の往復** | 3回以上(FAIL)。同一段落に「〜かもしれない」と承認語の両方があること |
| **現代語への翻訳** | 3箇所未満はFAIL、5箇所が目安 |
| **ビート16の限界と反証** | 追試・境界条件への言及(WARN) |
| **ビート5の予告リスト** | 列挙の形があるか(WARN) |
| **ビート1に数字を使っていないか** | 開幕は情景か逆説(WARN) |
| **ビート39の断罪** | 「あなたもまた」等の定型句が無いか(WARN) |
| 禁止記号 | 【】→:※!?…—()等が本文に無い |
| 中黒の用法 | カタカナ名の区切り以外に使われていない |
| 英字の残存 | カタカナ化漏れが無い(定着略称は除外) |
| シグネチャ | 末尾が規定の締め文 |

**FAILが1つでも残っている状態で納品してはならない。**

`--verbose` を付けると全ビートの字数一覧が出る。増築対象を探すときに使う。

## 第2段階:目視チェック(機械では測れない項目)

機械チェックが通ってから、以下を1項目ずつ確認する。

### 素材と構造

- [ ] **全ビートのうち、役割を果たしていないビートはないか。** 字数だけ埋まっていて中身が繋ぎ文になっているビートは無いか
- [ ] **手順から描いた主役研究が3本以上あるか。** 「誰が、いつ、何人に、何をさせ、何を測ったか」が書かれているか。結果の一行要約だけの研究は主役に数えない
- [ ] **研究引用は8〜12本あるか。** 各引用が「年号+機関+人名+N数+結果数値」のフルセットになっているか
- [ ] **ミクロ情景が4つ以上あるか**(ビート2・19・27・35)。場所+時刻+人物+動作+数字が揃っており、**二人称で書かれているか**
- [ ] **ビート1が情景か逆説の一行になっているか。** 統計・金額から始まっていないか
- [ ] **ビート2の情景が、ビート39で回収されているか。** 開幕で置いた絵にカメラが戻っているか
- [ ] **ビート5の予告が、結論を漏らしていないか。** 驚きの形だけを見せ、なぜかは一切言っていないか
- [ ] **ビート3の数字が、ビート20か24で再登場し、構成が環になっているか**
- [ ] **ビート17の飛び道具が、本当に「一見無関係な領域」から来ているか。** 同じ分野の研究をもう1本足しただけになっていないか。**直後に現代語の比喩が添えられているか**
- [ ] **ビート22の非対称が「Aは成り立つが、Bは成り立たない」の形で一行に圧縮できるか。** できないなら、この回の芯がまだ立っていない
- [ ] **ビート25が視聴者を作業に巻き込んでいるか。** 課題を出して考えさせるか、体験を追わせているか。**先に体験させ、後から名前を付けているか**
- [ ] **ビート30に、年号つきの具体的な事件と情景があるか。** 抽象的な「昔は違った」で終わっていないか
- [ ] **ビート24が冒頭と呼応しているか**

### 視聴維持

- [ ] **裏切り予告(13)が、視聴者の予想を正確に代弁できているか。** 誰も思いつかない予想を代弁しても効かない
- [ ] **想定反論(12・26ほか)が、機械が数えた回数だけでなく「本当に視聴者が思いつく反論」になっているか。** 藁人形を立てて倒していないか
- [ ] **想定反論のたびに、一度きちんと認めているか。** 「その指摘は全く正しい」を飛ばして「だが」に進んでいないか
- [ ] **現代語への翻訳が、視聴者がすでに知っている具体物になっているか。** 別の抽象語に言い換えただけになっていないか
- [ ] **各ブロックで最低1回、主張の切り返しがあるか**(反転の往復)
- [ ] **視点が回転しているか。** 当事者側→反対側→供給側→巨視側と回り、どの時点でも「まだ語られていない側」が残っているか

### 文体とファクト

- [ ] **煽り語(ヤバい、衝撃、絶対、驚愕)が無いか**
- [ ] **敬語がビート40〜41以外に出ていないか**(引用文中を除く)
- [ ] **比喩が1ブロックに2つ以上出ていないか**
- [ ] **丸めた数字を使っていないか。** 精密値が出せる箇所で「約〇割」に逃げていないか
- [ ] **実在しない研究・数値を書いていないか。** 記憶が不確かな箇所を精密値で偽装していないか
- [ ] **相関を因果と断定していないか**
- [ ] **実在の個人・団体を悪玉にしていないか。** ビート23で「〜が悪いという単純な話ではない」と明言しているか
- [ ] **ビート39が視聴者を断罪していないか。** 救済型・和解型・返却型・問い型のどれかで、**武器か赦しか問いを手渡して**終わっているか。「あなたもその構造の中にいる」と指を突きつけていないか
- [ ] **ファクトチェックリストを添付したか。** 確度「中」「要確認」の項目に、公開前検証が必要である旨を書いたか

## 増築の優先順位

不合格が出たときは、この順で直す。

1. **想定反論の往復を足す** — 視聴維持に最も効く。ビート12・26が既定だが、ブロックC・Eに足してもよい
2. **現代語への翻訳を足す** — 研究や概念の直後に、視聴者の日常の具体物へ対応させる
3. **脇役研究を主役研究に昇格させ、手順から描き直す** — 最も効率よく字数と密度が同時に増える
4. **巨視化ビート(30)に事件の情景を足す** — 年号・場所・人物・動作
5. **隠れた構造ビート(24)に制度・訴訟・法改正・回路を足す** — 年月つきで
6. **二人称のミクロ情景を追加する** — 場所+時刻+人物+動作+数字

**繋ぎ文や言い換えによる水増しは禁止。** 字数だけ増えて密度が落ちた台本は、字数不足の台本より悪い。

字数不足の主因は執筆時の手抜きではなく、**素材不足のまま書き始めること**である。増築しても埋まらないときは、工程1に戻って素材を探し直す。

## よくある不合格パターン

| 症状 | 真因 | 対処 |
|---|---|---|
| 総字数が5,000字前後で止まる | 工程1の素材が15行に届いていない | 工程1に戻る。テーマ変更も検討 |
| ブロックDが薄い | 非対称性を一行に圧縮できていない | 「Aは成り立つが、Bは成り立たない」を先に書く。金が絡むテーマなら原価構造・業界売上・利益率を台帳に追加 |
| ビート16が書けない | 主役研究の追試・批判を調べていない | 工程1に戻り、柱の研究それぞれの境界条件を1行ずつ調べる |
| ビート17が書けない | 飛び道具を用意していない | 暗号理論・動物行動・スポーツ・軍事・宗教・歴史から同型構造を探す |
| ビート25が用語解説になる | 名前を先に出している | 順序を逆にする。先に課題か体験をやらせ、後から理論名を付ける |
| ビート30が抽象論になる | 巨視化の型を決めていない | 歴史反転・進化起源・制度発明のどれで書くかを先に決め、年号か種名つきで特定する |
| 想定反論がFAILになる | 反論を「潰す」つもりで書いている | 代弁して**一度認める**。承認語を飛ばすと、この装置は機能しない |
| 台本が説教くさい | 悪玉を作っている。または視聴者を断罪している | ビート23と39を書き直す。犯人は構造に置き、視聴者には武器か赦しか問いを手渡す |
